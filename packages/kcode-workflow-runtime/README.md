# @koracode/kcode-workflow-runtime

A pure, hermetic candidate workflow kernel: the compiler, the static validator,
and the graph state machine, with nothing else attached.

It compiles an immutable definition bundle and walks its graph, producing a
deterministic decision stream, an affirmative terminal, and a typed output. It
performs no browser, model, database, filesystem, process, or network work.
Everything the world has to answer arrives through an injected action port, and
everything time-dependent arrives through an injected clock.

This is Phase 12.10 of `architecture-roadmap/12-KORACODE-CONTROL-PLANE-AND-RUNTIME-MIGRATION.md`.
Nothing selects this package as an execution engine. Removing it changes no
product behaviour and no data.

## What it decides, and what it asks

The kernel owns every decision that follows from the definition and the run's
own history: which edge, which terminal, which limit, which latch, what to
publish, and what to render into an instruction. It never performs an act.

| The kernel decides | The host answers |
| --- | --- |
| whether to attempt a hardened replay | whether the replay succeeded |
| which edge a condition takes | whether the page check passed |
| whether a node's expected outcome gates its success edge | whether that check passed |
| how many loop items run, and in what context | what each item produced |
| that a subworkflow may be entered, and at which pinned path | what the child's steps produced |
| which transition edges exist and what a failure route means | which edge was chosen |

```ts
import { compile, definitionBundle, fixedClock, runWorkflow } from "@koracode/kcode-workflow-runtime"

const program = compile(bundle)
const result = runWorkflow(
  { runID, resolver: program.resolver, rootAgentID: program.rootAgentID, runInput, clock: fixedClock() },
  {
    condition: () => ({ passed: true, detail: "url is …" }),
    verification: () => ({ passed: true, detail: "" }),
    agent: (request) => ({ status: "completed", output: `${request.nodeId} output` }),
    loopItem: (request) => ({ status: "completed", output: `item ${request.index}` }),
    transition: (request) => ({ status: "completed", edge: { edgeId: "…", to: "…", via: "handoff" } }),
    replay: () => ({ ok: true, detail: "3 step(s) replayed" }),
  },
)
```

`runWorkflow` is a thin synchronous driver. The state machine itself is a
generator (`runWorkflowGraph`), so an asynchronous host can drive the identical
semantics without the kernel ever learning about promises.

## How it is proved

The kernel is not asserted to match the incumbent runtime; it is diffed against
it. `vectors/deterministic-vectors.v1.json` is generated by driving the shipped
Python walker with its action boundary — and only its action boundary —
replaced by a script. Both engines are then told the same script, and every
decision, terminal, output, node state, event payload, and rendered instruction
is compared.

| Evidence | Where |
| --- | --- |
| differential parity over 226 scenarios | `test/differential.test.ts` |
| static accept/reject and digest parity over 95 graphs | `test/validation.test.ts` |
| property, fuzz, and metamorphic invariants | `test/properties.test.ts` |
| the hermetic-source audit, and proof it is not vacuous | `test/purity.test.ts`, `script/purity.ts` |
| 21 semantic mutations, each caught | `script/mutation.ts` |
| the vectors still describe the shipped walker | `workflows/tests/koracode/test_phase_12_10_runtime_vectors.py` |

The vectors derive from the Phase 12.9 conformance corpus and carry its digest,
so a report from this engine names the same corpus the reference ran. Cases the
kernel cannot model — a model's choices, the script bridge, the secret broker —
are listed in `skipped_cases` with the reason, never silently dropped.

## Commands

```
bun test test          # every suite
bun run typecheck
bun run check:purity   # the hermetic-source audit
bun run check:mutation # every semantic mutation must be caught
```

Regenerate the vectors from the reference runtime after any intended change to
its semantics:

```
cd workflows && uv run python -m tests.koracode.runtime_vectors.build
```

Every line of that diff is a change in workflow semantics that this engine must
also make.
